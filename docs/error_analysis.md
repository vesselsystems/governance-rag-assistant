# Retrieval error analysis

Numbers below come from [`reports/retriever_comparison.md`](../reports/retriever_comparison.md),
regenerated by `python scripts/compare_retrievers.py` (CI fails if it is stale).

## Why a second question set was needed

The original 15-question set in `evaluation/questions.json` cannot tell retrievers apart:
both TF-IDF and BM25 reach chunk-level hit@3 = 1.00 on it. Its questions reuse the
documents' own wording ("What belongs in an approval record?" against a section headed
*Approval record*), and its two unanswerable questions (travel reimbursement, sourdough)
share no words with the corpus, so abstention is never tested. It stays as a regression
check.

`evaluation/challenge_questions.json` adds 32 questions aimed at the known weak points
of lexical retrieval: 18 paraphrases that avoid the answering chunk's key words, 2
"lexical traps", 10 on-topic questions the corpus does not answer, and 2 off-topic
questions, split 15 dev / 17 test. The protocol (fixed retriever settings, metrics, and
the abstention-threshold rule) was written into that file before any result existed.

## Findings

**1. Paraphrases expose a large gap the original set hid.** Across the 20 answerable
challenge questions, both retrievers find an expected chunk in the top 3 only 65% of the
time (95% Wilson interval roughly 43–82%), against 100% on the original set.

**2. BM25 ranks better than TF-IDF, but the evidence is suggestive, not conclusive.** BM25
put an expected chunk first on 11/20 questions against 6/20 for TF-IDF. On the paired
questions, BM25 was right at rank 1 where TF-IDF was not five times, and never the
reverse: exact McNemar p = 0.0625. On the test split alone the gap is larger (8/11 vs
3/11), while on dev the two tie (3/9 each). With n = 20 that difference is not
established.

**3. A retrieval-score threshold cannot implement abstention for on-topic questions.**
With no threshold, every unanswerable test question retrieves "evidence" (6/6),
including *Who won the 2018 football World Cup?*, which matched "World Economic Forum".
With the threshold chosen on dev by the pre-registered rule, test still shows:

| Retriever | False answers (unanswerable given evidence) | False abstentions (answerable given none) |
| --- | ---: | ---: |
| TF-IDF, threshold 0.125 | 4/6 | 2/11 |
| BM25, threshold 4.50 | 3/6 | 3/11 |

The score distributions overlap almost completely: on test, the median TF-IDF top-1 score
is **0.18 for unanswerable questions and 0.15 for answerable ones**. Retrieval similarity
measures topical overlap, not whether a passage answers the question.

## Failure taxonomy

Each row is a real result from the per-question tables.

| Cause | Question | What happened |
| --- | --- | --- |
| Inflection (no stemming) | *Who does this guidance apply to?* | The answer (PPN chunk 0) says "applies"; "apply" matches chunks 1–2 ("may wish to apply", "continue to apply") instead. Both retrievers miss. |
| Synonyms | *Are bidders banned from using generative tools when writing proposals?* | The answer says suppliers' use of AI "is not prohibited"; banned/prohibited, bidders/suppliers and proposals/bids share no tokens. Both miss. |
| Synonyms | *Who can I phone with questions about this note?* | The answer is "Enquiries … Helpdesk on 0345 …" (chunk 9); "questions" pulls both retrievers to the Annex B disclosure questions. |
| Word form | *Do suppliers' answers about AI use count toward their evaluation score?* | The answer says "not scored"; "score" ≠ "scored", and "evaluation" pulls in the model-review playbook. Both miss. |
| Salient-word trap | *If a purchase raises defence or intelligence worries…* | "intelligence" matches "Artificial Intelligence" across Annex A; the answer (chunk 5) says "national security". Both miss. |
| Topic without answer | *How long must video conference transcripts be retained?* | TF-IDF returns the videoconference passage and BM25 the data-retention policy; neither states a period, but both look relevant. |
| Chance overlap | *Who won the 2018 football World Cup?* | "world" matches "World Economic Forum" (chunk 9). |

Where BM25 helped: frequency saturation and length normalisation stopped one repeated
term from dominating. For *Can a vendor feed our non-public tender papers into a model to
train it?*, TF-IDF ranked the model-review playbook first ("model"), while BM25 ranked the
answering PPN chunk first.

## A defect the retrieval metrics could not see

Writing a live-demo script showed that the evidence-only answer cut every quoted chunk at
650 characters, while 20 of the 23 chunks are longer (median 1,165). For *Can suppliers use
AI to write their bids?*, retrieval ranked the answering chunk second, so it counts as a
hit. But the answering sentence ("suppliers' use of AI is not prohibited") starts at
character 785, so the answer text the user read did not contain it. Chunks are now quoted
whole (still bounded by the 180-word chunking), and
`tests/test_rag.py::test_evidence_only_answer_quotes_whole_chunks_so_the_answer_is_visible`
fails on the old code. The lesson: measure quality where the user sees the output, not only
at the retrieval step.

## What this changes in the design

- **The evidence-only path can show plausible but irrelevant passages** for on-topic
  questions the corpus cannot answer. Today the UI only says "no evidence" when nothing
  overlaps at all. The honest fix in the current scope is labelling retrieved passages
  as *related passages, not a confirmed answer*. A real fix needs a different signal.
- **Abstention needs an answerability check, not a similarity cut-off.** Candidates: a
  reader model that must quote the supporting sentence or decline (needs a provider),
  or a cross-encoder or entailment model scoring question–passage support (needs a new
  dependency). Both are untested here.
- **Semantic retrieval is the next retrieval experiment.** Every miss above is
  vocabulary mismatch, which is what embeddings address. A BM25 + embedding hybrid is the
  usual next step. It needs a new dependency and a model download, so it was not run
  without approval.

## Limitations of this analysis

- Small samples: 20 answerable and 12 unanswerable challenge questions. Intervals are
  wide and the dev/test split difference is a reminder of that.
- Questions and labels were drafted with AI assistance (`label_status:
  ai_drafted_unverified`). A person still needs to check every label against the
  document; see [`evaluation/label_review.md`](../evaluation/label_review.md).
- One process wrote both splits, and none of these are real user questions.
- Chunk labels depend on the 180-word / 40-word-overlap chunking; changing chunking
  requires relabelling.
- Retrieval only: no generator was called, so nothing here measures answer quality,
  faithfulness, latency, or cost.
